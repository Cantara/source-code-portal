| P-20 | Features own their data: a feature's values on a repository are typed facets (`snapshot.Facet[T]`, a constant of the feature, no package variables), what it derives over all repositories an index it registers at the publisher (`snapshot.Index[T]`); a feature that shows another's data takes a function wired in `cmd/scp`; feature-only GitHub calls live in the feature over `github.Source.REST`; events are names. One contract, `api/openapi.yaml`, whose schemas the features share. Web: route modules, shared query keys, panels composed in `app/`, layers checked by ESLint | `plan.md` section 2, `design/sync-snapshot-store.md`, `design/github.md`, `design/catalog.md`, `design/web.md` |

| P-23 | Dependency updates: Renovate merges patch, minor, digest and pin updates itself once CI is green; major updates are PRs a person reviews and merges | `design/build-ops.md`, `.github/renovate.json` |
| P-24 | A product group is how its owner sees that something needs attention: each repository has a health score (100 less the penalties of its findings) and a group weighs its counted members (recent ones twice, the default repository three times more), never good while one member needs attention; every lost point is a visible finding. Vulnerabilities and build status are not signals: they need services and data the portal does not have, and vulnerability counts on a public page disclose weaknesses | `design/health.md` |
| P-25 | The commit navigator keeps per repository 500 default-branch commits, the 10 newest other branches (100 commits each, `renovate/` and `dependabot/` left out) and the 100 newest tags, read incrementally with a full re-read daily; a repository's history is drawn as a graph, a product's commits as a timeline grouped by day (repositories share no parents); diffs, changed files and write actions stay on GitHub | `design/commits-navigator.md` |
| P-26 | The portal publishes its catalogue as a KCP org hub: `/knowledge.yaml` (one manifest, a unit per group, README and document, each path an existing Markdown address; `depends_on` from the manifests' internal dependencies; at most 5000 units and 20 documents per repository) and `/.well-known/kcp.json`. It lives in `llms` because it shares that package's per-view build, cache and text cleaning; built from the viewer's view, so private repositories never reach a public viewer. `validated` is the day the portal read the document, not a review. Repositories' own `knowledge.yaml` files are not read or federated yet | `design/http-api.md`, `docs/api.md` |
