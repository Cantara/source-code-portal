# Verification of design unit 17-web-foundation (frontend foundation)

Date: 2026-10-14. Verifier: independent (not the author). Documents: `20-design/17-web-foundation.md` and its prototype `20-design/17-web-foundation.assets/` (web tree, `api/`, `go/cmd/e2eserve`, `pins.py`).
Scratch work: the session scratchpad `verify-17-web-foundation/` (copy of the prototype with node_modules, the pre-edit design `17-web-foundation.pre-edit.md`, a copy of the 06 prototype with `e2eserve`, `pinscheck.py`, probe tests, edit scripts).

## 1. Result

**Verdict: ready with caveats.** 25 findings: 11 major, 14 minor. 23 fixed (in the design document and, where the prototype was wrong, in the prototype with regression tests), 2 open and recorded with defaults (V-23 admin-listener seam with unit 18, V-25 redocly pin conflict with units 06/07). No blocker: the foundation built, type-checked and passed its gates as claimed, but eight behaviours of the shared layers were wrong in ways the original tests did not catch (a hot retry loop, a reload loop, focus theft, a stale announcement, wrong locale, a wrong server-state flag, a leaked server string, a lint hole), and the document contradicted its own code in six places.

State after the fixes (Node 26.10.0, pnpm 12.10.1, Go 1.27.1): `pnpm check` green (check-pins, prettier, tsc 7.0.2, eslint `--max-warnings 0`, **144 unit/tooling tests in 21 files**, was 130/20); `pnpm test:browser` **2** tests in real Chromium, was 1; `pnpm build` green (initial JS 139.2 KB of 200, CSS 17.5 KB of 25, `verify-dist` ok); Playwright through the real `internal/webapp` of the 06 prototype under the enforcing CSP incl. Trusted Types **62 passed**, was 60; `go build ./...` and `go vet ./cmd/e2eserve ./internal/webapp ./web` clean against the 06 prototype as verified at 03:06; the whole suite also stays green after refreshing the prototype's `api/` copies to the 07 documents of 03:12 (new slug, docId and timestamp patterns).

Changed files: `20-design/17-web-foundation.md` (edited, "Verification log" appended), `20-design/17-web-foundation.assets/**` (`web/src/lib/api/{client,problem,site}.ts`, `lib/format.ts`, `lib/persist.ts`, new `lib/stale-chunk.ts`, `lib/doc-id.ts` removed, `main.tsx`, `app/router.ts`, `shared/{problem-alert,problem-title,announcement,route-announcer,external-link}.tsx`, `scripts/{budget,verify-dist,lint-rules.test}.ts`, `eslint.config.js`, `vite.config.ts`, `e2e/{pages,routes.spec}.ts`, new tests, `package.json` + `pnpm-lock.yaml` (recharts), `locales/en/messages.po`, `api/*.yaml` refreshed). ## 4. Guardrail traceability (c)

The foundation's guardrails were each checked for a mechanism: live updates poll the snapshot version and stop while the tab is hidden (GR-40); fonts, scripts and syntax highlighting are self-hosted and served under `'self'` (GR-18, GR-19); site metadata shows the last full sync and the repository count, never the render time (GR-26); commit rows show initials, no third-party avatar request (GR-18, GR-35); there is no hard-coded banner or inline `style=` attribute (GR-14, GR-18); the theme is applied before first paint by the external `theme-init.js` and the icon set is inline SVG (GR-39); the group repo-count badge is a local URL (GR-33).

Trace completeness: grepped `02-design-guardrails.md` and architecture 20/21 for layout, theme, template, asset, banner, header, favicon, polling, CSS and JS concerns (the dashboard, layout, theme, highlighting, embedded assets, site metadata, badge and pages features; GR-11, GR-14, GR-15, GR-16, GR-18, GR-19, GR-28, GR-32, GR-35, GR-37, GR-38, GR-39, GR-40, GR-42).
