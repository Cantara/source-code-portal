## Guardrail traceability

The unit's guardrails were each checked for a mechanism: one composition root and one build that produces one binary (GR-01, GR-45); the image is built from a digest-pinned distroless base and fetches nothing at runtime (GR-45); readiness and liveness are separate probes (GR-41); CI owns every check, and verification scripts assert rather than print (GR-43, GR-44); the asset build runs only in the frontend toolchain and its output is the only thing embedded (GR-19); repository matchers are typed (GR-09); credentials travel in headers only (GR-13); the management plane is a separate listener that reflects nothing (GR-17); the default log level is INFO with structured fields (GR-42); periodic work is scheduled by completion time, not at a fixed rate (GR-24); Renovate runs with the repository's own preset (GR-45).

Library and tool facts re-checked on 2026-10-14: golangci-lint v2.14.0 (2026-09-24), GoReleaser v2.18.3 (2026-10-09), cosign v3.1.3, syft v1.54.1, oapi-codegen v2.8.0, oasdiff v1.33.0, go-licenses v2.0.1, govulncheck v1.9.0, pnpm 12.10.1 (2026-10-06; 12.13.0 exists), Node 24.21.0, Go 1.27.2; all 14 action SHAs resolve to their commented tags; the three base-image digests match the registries; GoReleaser `dockers_v2` build context and `docker_signs.artifacts` default as assumed; `gh release download` and `gh release edit` handle draft releases; `docker buildx imagetools inspect --format` prints the digest; `pnpm/action-setup` v6.1.0 reads `package_json_file` and `devEngines`. The Go behaviour that an unhandled SIGHUP terminates the process was reproduced, not only read.

## Residual risk

- The product `wire.go` (4.2.2, 4.2.3) is a specification, not compiled code: unit 05 ships no code assets (U-6), so `github.New`, `CheckCredentials`, `Doctor`, `RunAppManifest`, `Verifier` and `ReloadKeys` are checked against 05's document and a stand-in only. The corrected listing should be re-run against the union when 05 lands.
- Carried cross-unit findings are still open: U-1 and U-2 (08's `catalog.Config` against `config.Describe` and the one-key matcher shape; `deploy/dev.yaml` and the k8s ConfigMap use that shape and will not lint until U-2 is resolved), U-3 (five route-literal hits in `internal/catalog`; reproduced after the rule change), U-4, U-5.
- The listeners open after the store is opened and the warm start decoded, so a very long open or migration leaves `/livez` silent; the example manifests and the smoke test allow for it (`startupProbe`, `start_period`), an early minimal listener is Q16-19.
- `webhook.self` and `git.*` doctor findings are specified but not built (Q16-21); `store.check` as a task flips the store to degraded on failure (03 Q10), which this unit relies on without a test.
- The large-sort assertion of ADR-017 is not in `smoke.sh` (V16-24, Q16-20).
- Not exercised: the cosign signing, SBOM and attestation steps (they need a real OIDC token and a registry), FULL-mode smoke, e2e, Lighthouse, Schemathesis and the Kubernetes example (no `kubeconform`, Q16-17); the release workflow was checked with `actionlint` and a snapshot build only.
- `runcommand.go` is unix-only (`//go:build unix`); the release matrix is linux and darwin. A Windows developer cannot run `token_command`.
- Nightly fuzz sharding assumes at most 14 targets per shard (120 minutes at 8 minutes each); at 56 targets the matrix needs a fifth shard (stated in the workflow).
