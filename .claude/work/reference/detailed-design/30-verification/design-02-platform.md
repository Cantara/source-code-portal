# Verification report: design unit 02-platform (2026-10-14)

Verifier: independent (not the author). Document verified and edited: `20-design/02-platform.md` (companion `02-platform.assets/` also corrected: code, tests, generated `out/`, README; `go.mod`/`go.sum` unchanged). Scratch module: the session scratchpad `verify-02-platform/` (`proto/` working copy, `final/` clean copy used for the final run). Toolchain go1.27.1 darwin/arm64. No other unit's document was touched.

## Verdict

**ready_with_caveats.** The design is complete (15 sections plus Appendices A-C, open questions carry defaults) and the prototype it rests on was real: it compiled, vetted and passed `-race` before any change. It was not correct in several places that an implementer would have copied: the shutdown budget contradicted the architecture (45 s grace, design claimed 90 s and summed to 55-75 s), a recovered panic and any response written outside the header writer carried no security headers, `Rate` silently mis-scaled `/h` rates, the webhook limiter's counter contradicted unit 04's "no bridge", the route classification table was incomplete against the route table (it would have failed its own completeness test on day one), and `netguard` denied only exact metadata addresses. All of these are fixed in the document and in the prototype, each with a regression test. What remains are documented residual risks, cross-unit contracts for other owners and three things that could not be verified (below).

## Checks

(a) **Architecture conformance.** Non-test imports match matrix 5.2 except the two recorded deviations D1/D2 (checked by reading every import block and `go list`): `secret`, `netguard`, `telemetry`, `lifecycle` import no internal package; `logx` imports `secret`; `config` imports `secret`; `httpx` imports `logx`, `secret`; equal rank never imports equal rank. The consumer-interface assertions of 2.3 compile (`consumers_test.go`). Signatures in section 3 were compared with `go doc` of every package: one omission (`netguard.PrivateNetworks`) and the new symbols were added. Deviations against architecture text that the document recorded (D3 recover order, D9 `Secret` pointer, D11 UUID, D12 `Close` skipped on timeout) were re-checked and are justified (D9's `%p` leak was reproduced by the author's test and re-read here). New deviations recorded: D14 (httpx/telemetry tests import the OTel SDK; same allowance unit 14 asks for), D15 (`server.admin.allowed_hosts`, one `servers` stage). Architecture 10.1 step 8 lists the rate-limiter sweeper inside the refresh stage; the design keeps it as its own stage (explained in 8.3; the architecture names the worker, not the stage).

(b) **Completeness.** All 15 sections present and concrete; nothing is deferred without an open question and a default. Gaps closed: headers-file grammar (V-20), `Observe` outcome mapping (V-13), route classes for four route names (V-05), `Without("admin.metrics")` (V-06), startup shutdown-budget check (V-02).

(c) **Guardrail traceability.** Trace table checked against every guardrail of `02-design-guardrails.md` and the operational, configuration, packaging and access features in scope for the platform unit: missing guardrails added (V-10): GR-01, GR-03, GR-04, GR-11, GR-12, GR-14, GR-20, GR-24, GR-27, GR-35, GR-41, GR-45 (and the build-provenance, packaging and logging rows they imply). Every row carries a concrete mechanism (type, test, lint, archtest, CI or design).

(d) **Technical correctness.** Prototype run before changes: `go vet` clean, `go test -race -count=1 ./...` green. Library facts re-checked against the live sources on 2026-10-14: `go list -m <module>@latest` equals the pinned version for every module in 2.1; `go.dev/doc/go1.27` confirms the `uuid` package and `Server.MaxHeaderValueCount`; pkg.go.dev confirms the `ssrf` options, `Guardian.Safe` and the `tcp4`/`tcp6` rule, and the `otelhttp` options used. Probe tests written and run: secret echo in violations (none), alias bomb ("excessive aliasing", 0.7 ms), merge keys, duplicate keys, 1xx handling, `ResponseController` through both chains (works), `HTTP_PROXY` handling, localhost rebinding, link-local allow-listing. Fuzz re-run after the corrections: `FuzzRate`, `FuzzClientIP`, `FuzzLoadFile`.

(e) **Testability.** 11 tests added, 1 weak assertion strengthened (V-21); outbound-client hardening (GR-22: no environment proxy, no redirect following by default, rebinding) now has tests; the panic-header, silent-handler, interim-response, Host-guard, counter, `ServeAll`, `_FILE` collision, endpoint shape and shutdown-arithmetic regressions each have a named test. Remaining planned-only tests are listed in 12.3.

(f) **Security / races / lifecycle.** No data race found (`-race`, lifecycle `-count=3`). Lifecycle bugs found: sequential server stages doubling the worst case (V-02). Security: missing headers on recovered responses (V-01), metadata exposure through an allow-listed link-local range (V-08), credentials in an OTLP endpoint URL (V-07), DNS rebinding of the admin listener (V-15, mitigated, default off), residuals documented (V-17).

(g) **Buildability.** An engineer can implement from the document plus assets. The questions they would have had to ask are now answered: how the shutdown budget is computed and why, who counts the webhook rejection, how each route is classified, what the headers file looks like.

## Unresolved

1. **Admin DNS-rebinding guard is off by default** (V-15, Q15). With no bearer token and no `allowed_hosts` the admin listener is only as safe as its network; the startup warning says so. Owner decision.
2. **`fd20:ce::254` (GCE IPv6 metadata address) not verified** by a web source; kept in the deny list (harmless).
3. **Cross-unit contracts, not owned here**: Markdown branch of `httpapi.Negotiate` should set its own sandbox CSP (Q17, units 06/overview); `github:` mapping ownership split (Q2, units 04/05/08); units 03/05/14 `Validate` shapes (Q1); archtest rule for SDK imports in `_test.go` (D14, build unit).
4. **Not compiled** (as the author already said, still true): the headers-file parser, the `scp config` subcommands, the route classifier and `TestRoutesClassComplete`, the glue types of 6.1.1, the `scp_ratelimit_keys`/`scp_lifecycle_phase_seconds` instruments, `otel.SetErrorHandler` wiring, `goleak`.
5. Residual risks of V-17 are accepted by design, not fixed.
